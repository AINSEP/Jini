# @jini-ai/renderers-react

A React artifact-renderer registry and sandboxed `srcDoc` host for a chat/artifact frontend:
resolves which renderer (Markdown, HTML/SVG, a React component, or a host-supplied one) should
display a generated file, then renders it — HTML/SVG through a sandboxed iframe with CSP and a
storage/focus-guard shim, Markdown through `micromark` + GFM with Shiki syntax highlighting. Also
ships an annotation-canvas overlay, new-tab preview, and a preview-modal shell.

## Install

```sh
npm install @jini-ai/renderers-react react react-dom
```

`react`/`react-dom` are peer dependencies (`^18.3.0 || ^19.0.0`). `@jini-ai/chat-core`,
`micromark`, `micromark-extension-gfm`, and `shiki` are regular dependencies — no optional peers.

## What you get

- **Renderer registry** — `RendererRegistry` (`.resolve`, `.register`, `.list`), the
  `ArtifactRenderer`/`ArtifactRendererContext`/`ArtifactRenderMatch` contracts, and
  `resolveArtifactManifest`. `createDefaultRendererRegistry()` seeds one with the four renderers
  this package ships — `HtmlRenderer`, `MarkdownRenderer`, `SvgRenderer`, `ReactComponentRenderer`
  — deliberately excluding `deck-html` (needs a host-injected postMessage bridge; register your
  own).
- **The `<ArtifactView>` component** — resolves an `ArtifactFile` against a `RendererRegistry` and
  renders the match, with an optional `annotation` prop that wraps the result in an
  `<AnnotationCanvas>` overlay and `slots` for a host to override any part of the fallback chrome.
- **Markdown and highlighting** — `renderMarkdownToSafeHtml`, `highlightCode` (Shiki), and the
  `<Markdown>`-adjacent `MarkdownRenderer`.
- **Sandboxed `srcDoc` host** — `buildSrcDoc`/`buildLazySrcDocTransport`/
  `canActivateSrcDocTransport`, `DEFAULT_SRC_DOC_CSP`, `applySrcDocBridges` and the
  `injectAfterHeadOpen`/`injectBeforeHeadEnd`/`injectBeforeBodyEnd` splice helpers, plus the
  `<SrcDocSandbox>` component and `shouldUrlLoadHtmlPreview`/`parseForceInline`/
  `htmlNeedsFocusGuard`/`htmlNeedsSandboxShim` load-decision helpers.
- **A second, independently-built sandboxed-iframe core** — `isFullHtmlDocument`,
  `wrapFragmentAsDocument`, `injectBaseHref`, `buildStorageShimScript`, `buildFocusGuardScript`,
  `buildSandboxedDocument`, and `useSandboxBridge`. This traces back to the same OD original as the
  `srcDoc` host above but is not behaviorally identical (see the module doc in `src/index.ts` for
  the exact DOMParser-fallback difference) — it's `@jini-ai/ui`'s `html-viewer` feature's chosen
  core, kept alongside rather than merged. Its string-splice helpers are re-exported here under an
  `injectAfterHeadOpenStringOnly`/`injectBeforeHeadEndStringOnly`/`injectBeforeBodyEndStringOnly`
  suffix to avoid shadowing the `srcDoc` host's own names.
- **New-tab preview** — `buildSandboxedPreviewPage`, `openSandboxedPreviewInNewTab`.
- **Annotation canvas** (`./annotation-canvas`, re-exported at root) — `useAnnotationCanvas`,
  `<AnnotationCanvas>`, `AnnotationCanvasPort` (with a `createFakeAnnotationCanvasPort` test
  double), and the pure geometry/rule helpers (`computeDockPlacement`, `normalizedRectFromPoints`,
  `buildSubmitOptionRules`, ...).
- **Preview modal shell** (`./preview-modal-shell`, re-exported at root) — `usePreviewModalShell`,
  `<PreviewModalShell>`, and the pure `computeScalerStyle`/`computeStageScale`/
  `deriveContentStatus`/`resolveInitialViewId` rules.
- **i18n** — `<I18nProvider>`, `useI18n`, `useT`.

## Usage

```tsx
import { ArtifactView, createDefaultRendererRegistry } from '@jini-ai/renderers-react';
import type { ArtifactFile } from '@jini-ai/renderers-react';

const registry = createDefaultRendererRegistry();

function Preview({ file }: { file: ArtifactFile }) {
  return <ArtifactView file={file} registry={registry} />;
}

const markdownFile: ArtifactFile = {
  name: 'summary.md',
  kind: 'text',
  content: '# Summary\n\nGenerated by an agent run.',
};
```

## What's swappable

`RendererRegistry` is the seam: `.register(renderer)` adds or replaces a renderer by `id` (e.g. a
host's own `deck-html` or a custom kind), and `createDefaultRendererRegistry()` is a convenience
default, not a fixed set. `ArtifactView`'s `slots` and `annotation` props are likewise real
injection points. Fixed: the two sandboxed-iframe cores' CSP/shim mechanics themselves, and the
Markdown pipeline (`micromark` + GFM is not swapped per-call).

## Runtime

`jini.runtime: "browser"` — every export assumes a DOM/React runtime (iframes, `postMessage`,
`window`).
ESM only — ships `"type": "module"` with no CommonJS `require` build.
