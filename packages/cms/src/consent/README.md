# Consent mechanism

This is a mechanism, not legal advice or a compliance verdict. Hosts own policy copy, purposes, category classification, and review. The engine does not load a CMP or contact a geo service.

Imports: `@jini-ai/cms/consent` (universal decisions/contracts), `/consent/html` (Node parse5 transform), `/consent/express` (HTTP lifecycle), `/consent/node` (immutable file receipts behind the existing atomic-writer port). Admin view: `@jini-ai/admin/consent/react`.

Declare scripts in theme/plugin HTML:

```html
<script data-consent-category="necessary" src="/essential-navigation.js"></script>
<script data-consent-category="functional" src="/optional-chat.js"></script>
<script data-consent-category="analytics" src="https://tags.example/analytics.js"></script>
<script data-consent-category="marketing" src="https://tags.example/ads.js"></script>
```

Unclassified third-party executable scripts default to marketing; local/inline scripts default to functional; unknown categories are blocked. A necessary label in HTML grants no exemption: bind exact `necessaryScripts` entries from host-owned manifests in the HTTP/gate options. Necessary scripts must contain only essential behavior, including everything they dynamically import/load. Optional tracking cannot be hidden in an essential script, inline event handler, CSS URL, iframe, or image pixel. The delivered-HTML gate also defers frames/srcdoc, media, external/pixel images, noscript pixels, external stylesheets, remote CSS/font requests and inline event handlers; all resource hints including prerender are removed. Gating uses parse5 with scripting disabled so no-JS pixels are visible to the transform. Ordinary local images/styles remain page content, including local or `data:` CSS backgrounds and fonts (CSS escapes are decoded before the check). Repeated `<html>`/`<body>` start tags and duplicate attributes are normalized by re-serializing the parsed tree before gating, preserving the original doctype and document mode; an attribute that must change but cannot be located fails the transform (restrictive fallback) rather than passing through. A restrictive style/font/image/media/frame/connect CSP precedes them while marketing is denied, blocking hidden remote imports/fonts; host-reviewed `categoryOrigins` add each granted functional/analytics category's origins (for example an analytics collector) without granting marketing; browser-only GPC installs the same policy before site styles parse. Dynamically generated requests by host-allowlisted necessary scripts still require host classification of that resource owner. External CSS/fonts are conservatively treated as marketing, including those imported by local CSS. JSON and JSON-LD remain data. Existing authored templates remain inert; nonessential SVG/MathML scripts are removed because templates there are not inert HTML templates. Do not use the reserved `data-jini-consent-*` markers in author HTML.

The response transform keeps script elements inside inert HTML templates until a durable visitor choice exists. Browser release preserves document order, consumes each template once and retains script attributes (including nonce). An external script that fails or exceeds 15 seconds cannot hold subsequent scripts forever. Asynchronous/vendor-specific dependencies still belong to the script owner. Scripts inserted dynamically after page delivery must go through a consent-aware integration; the engine cannot undo a vendor script that a necessary script chose to run.

Unknown region, EU and UK use opt-in. Only ISO subdivision `US-CA` selects opt-out in auto mode. Hosts may supply the region port from an explicitly trusted edge header; strip visitor-supplied copies at the edge. No header is used by default. Opt-out allows optional categories before a first choice; rejection persists denial and GPC still wins. Read failures force denied opt-in behavior even in opt-out regions. GPC (`Sec-GPC: 1` or `navigator.globalPrivacyControl === true`) denies analytics and marketing even over saved grants. This conservatively includes analytics tags that may share data.

Native forms/details keep necessary/default rejection working without JavaScript. With JavaScript, a failed grant keeps the previous choices and shows the server error. A failed withdrawal applies its denial at once: denial signals, a host-only `__Host-jini_consent_withdrawal` client cookie on HTTPS (`jini_consent_withdrawal` on HTTP) that restricts choices (and adds the resource CSP) on later pages for up to the receipt lifetime, and a reload so running scripts stop. Later pages retry denial-only saves derived from the effective choices after throttling/server/network failures; cookie values never supply request bodies. Automatic retries share a save queue with explicit submissions, keep preferences synchronized, and never reload to apply grants. The cookie is cleared once matching denial evidence is durable. Legacy HTTPS withdrawal markers migrate as non-retrying denial limits; if a legacy domain cookie survives a durable choice, a protected host marker shadows it so it cannot trigger repeated saves or undo that choice. After a choice, the banner collapses to a closed disclosure whose summary (the host's preferences label) is a small corner control that reopens the preferences, also without JavaScript. A successful changed choice reloads the page because already-running vendor code cannot be reliably unloaded. No-script rejection is an ordinary POST/303 flow. The visible native Do Not Sell or Share action denies analytics and marketing while retaining the submitted functional selection. Late DOMContentLoaded listeners registered by deferred scripts are replayed after ordered release without rerunning necessary listeners.

Consent Mode uses the basic behavior: default denied signals precede site scripts; saved/new choices enqueue update signals with `ad_storage`, `analytics_storage`, `ad_user_data`, and `ad_personalization` plus functional/security signals. No Google tag or cookieless denied ping is loaded by this package. `googleConsentSignals()` returns the narrowed `'granted' | 'denied'` literal type for every signal; `security_storage` is always `'granted'`, including when callers supply `necessary: false`. The policy module is the sole signal-mapping owner (`GOOGLE_CONSENT_SIGNAL_CATEGORIES`); browser code consumes that table.

Evidence has timestamp, choices, policy version, effective region mode, GPC and action. An unpredictable opaque ID identifies immutable evidence. Save proof durably before issuing the host-only HttpOnly/SameSite cookie. It is not an account or authorization token. Cookies/consent expire after 180 days; a policy-version change requires another choice. Cookie values never contain visitor identity. Proofs collect no IP or user-agent; rate limiting uses the host's existing transient counter policy. HTML is private/no-store to prevent cached visitor grants crossing requests. HTML policy/proof failures never produce a page 503: unreadable/invalid proof is absent with denied defaults, last-good configuration survives read failures, and an OFF configuration is a no-op. An unknown cold configuration fails safe with denied HTML; even a site whose settings are OFF may temporarily see the unavailable banner until its first successful config read. A rejected transform (including a throwing reporter) completes with inert plain text and a restrictive response CSP. Enabled pages larger than `maxHtmlBytes` (default 5 MiB) use the same fallback, discarding the original HTML and later stream chunks; the capture bound uses Node write backpressure while policy resolves. Enabled/static policy is checked before overflow handling: static export still receives 409, and disabled pages retain all original bytes without a consent CSP. A malformed present receipt cookie or a cookie whose stored receipt is missing is failed proof, never a new visitor, so opt-out regions cannot turn an evicted rejection into a grant. Buffer, end, pipe and sendFile HTML share the transform; non-HTML output never reads policy/proof. Save failures return an actionable API error and never issue consent. The host must inject an error reporter and write limiter. Receipt readers may return `{ id, present }` to distinguish absence from malformed proof; legacy `string | null` readers are checked against the configured cookie name when they return null.

External CMP extension point: OneTrust, Cookiebot and CookieYes integrations may adapt vendor choices into `ConsentRecordPort` and the existing policy/HTML gate. They must preserve GPC precedence, version invalidation, save-before-grant and one release owner. Vendor scripts themselves remain gated. No adapter is implemented or vendor credential collected here.

Static export apps must use `delivery: 'static'`: consent ON refuses HTML export with HTTP 409 and an actionable explanation; consent OFF preserves the page. Static sites cannot durably POST a receipt, and publishing permanently inert theme scripts breaks their behavior. Node receipts default to the 180-day cookie lifetime (`retentionMs` is configurable) and 10,000 records per directory. Serialized saves expire old proof and evict oldest-first at capacity rather than permanently refusing new visitors; capacity eviction can shorten retention. Hosts requiring a longer proof period must configure retention and capacity accordingly. The inventory is scanned once per directory and maintained across writes. Multiple processes sharing a proof directory need host coordination for a strict global cap. Bind `consentRateLimitKey` after trusted IP resolution to group rotating IPv6 addresses by /64. Supply host-reviewed theme origins with `resourceOrigins`; authored HTML never supplies the CSP allowlist. Supply request-specific CSP nonces through the HTTP `nonce` callback; the injected runtime uses a fresh per-response identity token.

Primary references: [Google Consent Mode setup](https://developers.google.com/tag-platform/security/guides/consent) and [W3C GPC specification](https://www.w3.org/TR/gpc/). These establish technical signals, not legal coverage.
