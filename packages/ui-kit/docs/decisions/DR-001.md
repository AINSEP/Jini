# DR-001 — UI storefront with a framework-free contract

Status: Accepted owner decision
Date: 2026-10-03
Contract: 1.0.0
Package: @jini-ai/ui-kit 0.1.0

## Inputs and problem

The owner-approved Round 5 consensus and binding v1 decisions require reusable screens to request component roles from a host-selected kit. Importing UI primitives through an admin or feature package couples unrelated packages, and framework dependencies must not enter a headless or different-framework consumer.

## Decision recorded

Use one package with framework-free root contracts/rules and framework-specific subpaths. Root has no runtime dependencies. React, React DOM, and Vue are optional peers plus development dependencies. React v1 resolves 16 facade components through a provider with native defaults; partial overrides, extension, and a strict complete-kit variant serve different host needs. Every component can be replaced, including ConfirmDialog.

Safety belongs to a framework-free controller with latest-policy reads and guarded actions. Confirmation views receive controller bags, never raw destructive callbacks. Cancel-first focus, pending dismissal blocking, human-only agent-handle withholding, and consequence labels are explicit contract obligations. Development mounted-DOM diagnostics default to native fallback and can be set to warn or off; fallback uses native actions too, because the original Button override may be the source of failure.

Agent handles and metadata arrive through a host port. No agent-runtime package is imported. Context identity uses a shared global symbol for contract major 1, with a development warning on version skew. Opaque attrs target the actual documented focus target. Select keeps native semantics for a library-independent driver.

Native styles are optional, layered, and keyed on parts. Toast state belongs to each service instance; the host mounts its ToastRegion. Browser-only conformance remains explicitly tagged and separate from jsdom evidence.

## Consequences and deferred work

Screen imports can remain stable as hosts replace component libraries. Hosts must implement the semantic contract, forward refs/attrs, and run conformance/browser validation. A development guard does not authorize destructive actions in production. Sharing a context does not remove the need for a compatible host React runtime.

Planned spec entries have no stub component behavior. Vue/Angular subpaths, library adapters, motif loading, and consumer migrations are not implemented in v1. Migrate admin's provisional kit/confirmation first with direct imports and no forwarding shims; keep panel-kit logic separate. Follow with user-management, chat, and reusable UI features in separate jobs.

## Delivery boundary

This decision records supplied owner choices; it adds no architecture or security policy. Source/README/spec work is confined to ui-kit. Initial development used package-local dependency links because pgrep was unavailable, so no install step was run and this task left the lockfile unchanged. Executed test status belongs in the delivery report, not this decision record.

Output: package boundary and customization rationale. Risk: custom adapters can satisfy types while violating mounted behavior. Suggested next assignee: consumer migration owner, then browser conformance owner.
