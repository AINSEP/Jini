The tool-execution routes are returned as data: `toolExecutionRoutes({ executor, listToolsFor, env, host }, { tokenEnvVar, maxBodyBytes, runWithContext, authorizeRun, onInternalError })` replaces `registerToolExecutionRoutes`; `requireToolExecutionCaller`, `streamToolExecution`, `ToolExecutionRouteTarget` and `nodeTimingSafeEqual` are removed (no alias). The caller check is one decision, `toolExecutionCallerRefusal({ authorization, peerAddress, env, timingSafeEqual }, { tokenEnvVar })`, which a host with other private routes adapts to its own framework. `env` is required (the daemon no longer reads `process.env`) and the constant-time compare is the host's. The host run check is now the typed `AuthorizeToolRun` port: it sees the raw parsed body (or the catalog query) before validation and answers `{ allowed: true, principal? }` or `{ allowed: false, response }`; a returned principal replaces the one in the body. Same order as before: caller gate, body (413/400), run check (403), validation (400), execution. A compressed request body is now refused with 415 (the daemon never unzips). The execution answer is written on the line stream; the catalog answer carries `cache-control: no-store` and no ETag.
