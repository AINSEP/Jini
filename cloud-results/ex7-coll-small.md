- **Check order (all K1 specs):** http-kit's adapter runs workspace → authenticate → parse → handle. Hand-written routes parsed the body before reading the principal, so a request with **no principal and a bad body** now gets the auth failure instead of a 400. Unreachable behind the session middleware; three Tovu tests forced it with direct handler calls and no principal (`admin-menus-routes` ×2, `admin-widgets-routes` ×1). They now set the seeded owner principal; assertions unchanged (`8b6171bcfd`, `4526a9c791`).
