## STOPPED: `frontend-sessions` + `frontend-control` (and with them G3 `frontend-request-route`, `surface-*`, `frontend-guest-scope`)

Plan STOP rule: "a host hook in Tovu reads something a web `Request` + `locals` + `client` cannot give it". The hooks Tovu passes (`visitor-frontend-control.ts`: `resolveOwner`, `resolveCapacityKeys`, `allowsRequest`) call `resolveClientIp(req)` whose fallback is Express's `req.ip`, and `resolveProtocol(req)` which falls back to `req.protocol`; both depend on the app's `trust proxy` setting, which a web `Request` + `client.address` does not carry. `adminFrontendOwner` reads `req.query.tabId` as Express parsed it (a repeated `?tabId=` is an array and is refused). Converting only the daemon side would change who owns a session / which quota key a visitor gets. Nothing was changed in these files. Owner call needed: either (a) the host builds the hook input (`isSecureRequest`, a trusted client-address port, parsed query) as required ports on `DaemonRouteHost`, as the plan's cookie row already does for `isSecureRequest`, or (b) keep these routes on Express until the proxy policy is decided. `frontend-guest-scope` (`req.secure`, `res.cookie`) and `frontend-request-route` (`resolveOwner({ req, res })`) share the same hooks, so they wait on the same answer.
