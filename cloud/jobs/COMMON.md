# Rules for every cloud job (11-05). Read before your job file.
Setup: `source /workspace/shared/dev-env.sh`; `/workspace/shared/start-postgres.sh`. Repos /workspace/Tovu, /workspace/Jini. Personas and skills: /workspace/Jini/AI-Dev-Shop (Tovu has none). Read agents/software-architect, agents/programmer, agents/tdd skills.md and say you loaded them.
Plans live on Jini branch cloud-plans-1105: `git -C /workspace/Jini show origin/cloud-plans-1105:cloud/plans/<file>`. TRIM.md overrides the plan; your job file overrides both.
Base: Tovu origin/night-1105 at e327c07c8, Jini origin/integ/night-1105 at 6f507852d, unless the job file names another base. Create your branch in EACH repo you change: `cloud/<job>` from that base. Rebuild Jini and `JINI_PACKAGES_DIR=/workspace/Jini/packages npm run link:jini` after changing Jini.
Caps: 2 hours wall clock. Commit by explicit paths and push every 10 minutes. On cap: push, report, END. Minor findings are LISTED, not fixed.
NEVER push to main, force-push, deploy or npm publish. No secrets in files. No live or owner data.
Tests: write the failing test first for bugs. Run only tests you touched or affected, in this container; fix what fails. Never weaken a test to pass. Same failure twice with no progress: stop on it and report. Also run tsc on touched packages and complexity lint.
Code: the SMALLEST change. You tend to overbuild: no new abstractions, frameworks, tables or options beyond the job. Reuse first. Generic logic in Jini behind ports, public functions (requiredObj, optionalObj), Tovu wiring only. Agent plugins are subpaths of @jini-ai/agent-plugins, never @jini-ai/plugin-<id>; plugins never import each other; no vendor code in core. Complexity ceiling 9 in apps/desktop, 10 elsewhere. No eslint-disable. Move "why" comments, never delete them. No generic user-facing errors. No boot refusals (warn). Users never fix anything by hand. No silent behaviour changes. Schema only via ADR-066 TS migrations registered everywhere. State cost: frequency × payload for each read/write/poll added.
Report last, in your final message and in cloud/reports/<job>.md on your branch: branches + shas, what changed, test results with exact commands, anything left open, bugs found on their own lines.
